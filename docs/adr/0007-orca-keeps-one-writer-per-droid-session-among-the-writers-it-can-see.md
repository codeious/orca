# Orca keeps one writer per Droid session among the writers it can see

Droid takes no lock on a session. A second process loads a held session without error and appends to the same file, two writers split the history into two chains, and an idle terminal never shows the other writer's messages. So Orca enforces one session holder itself, among the writers it can see: its own terminal panes, through their status rows, and its own chats. A Droid terminal session holds a session while a pane row carries its id and the `droid` process is not proven `exited`, whether the agent is working, idle, or `done`. A `live` holder blocks Resume in new chat and the row offers "Open terminal"; `unverifiable` asks for confirmation first; `exited` allows it. A chat that owns a session refuses every Droid resume command Orca sends, through the shared ownership guard extended with Droid's resume grammar. A fork is never a second writer, so it goes to the surface that does not hold the session. Writers Orca cannot see are outside the guarantee: a Droid in the user's own terminal, `droid exec -s`, the Factory App, and a command typed by hand in an Orca pane, which no agent's guard covers. We chose this because the ownership list already accepts any provider, and a process scan cannot tell which session a plain `droid` holds.

## Considered Options

- **Relying on Droid.** Rejected. It has no lock and gives no warning, and the holder never sees the other writer.
- **A Droid-only guard beside the shared ownership check.** Rejected. The ownership list is already provider-agnostic, and only its lookups and its resume parser name Claude and Codex, so a second guard would drift from the first.
- **Scanning processes for outside `droid` writers.** Rejected. A plain `droid` names no session on its command line, and a scan cannot see another host's processes.
- **Blocking on `unverifiable`.** Rejected. A lost verdict proves neither life nor death, so Orca asks and does not decide for the user.
- **Treating any Droid row that carries a session id as a holder.** Rejected. Orca keeps a dismissed row's session id for resume, so a row is not proof. The process verdict decides.
- **Moving the session to the target workspace with `droid.change_working_directory` on a folder mismatch.** Rejected. It is not a published contract, it needs a trusted folder, and the change lives in Droid's session index where the vault cannot see it.
- **Ending the process on a `SessionEnd other` once the lead and a `clear` marker are checked.** Rejected. It relies on the old session's `other` arriving after the new `SessionStart`, which a `SessionStart` hook past about 10 s inverts, and which was never measured for `/sessions`, `/compress`, `/handoff`, or a slow start on `/new`. A false end is permanent and lets Resume in new chat through on a live session.
- **Accepting the gap for a `SessionStart` command past about 10 s.** Rejected. A slow user command does not delay Orca's own post when both run, but Orca's own command running long and a user `hooks.json` that replaces only `SessionStart` remain ways to a false end, and the process check removes both.
- **Starting the watch only on `reason=other`.** Rejected. Two quick Ctrl+C on 0.245.1 sent `prompt_input_exit`, which that rule dropped, so Mission Control kept showing a live paused Mission after `droid` was gone and Send message may type into the pane's shell. The probe decides in every case, so the reason filter saved nothing.
- **Offering "Fork into new chat", for a held session or one recorded in another folder.** Rejected. A fork works with published calls (`droid.load_session`, `droid.fork_session`, then `droid.load_session` of the new id, with no prompt and the original untouched), but the chat would load a held session on purpose, which is the act this guard exists to stop, and it would add a second way to branch beside `droid --fork`. Claude and Codex fork only into a terminal. The folder case also needs the `droid.change_working_directory` call rejected above, and a moved fork keeps `session_start.cwd` on the old folder, so the vault would list it there and refuse Resume in new chat from the workspace. `droid exec --fork` is refused over `stream-jsonrpc`.

## Consequences

- Droid hooks must capture the `droid` process identity (pid and start time) as Claude's do. Today only Claude's hook script does, so a Droid terminal row has no verdict. ADR 0005's Mission liveness needs the same identity. Until a Droid terminal has one (Windows, rows saved before the capture), its verdict is `unverifiable` and Resume asks. A task ticket checks that a hook command's parent process is the `droid` TUI and picks the fallback if it is not.
- A Droid `SessionEnd` never ends a terminal's process by itself. `reason=other` marks a real exit and also the old session's late event after `/new`, `/tree`, and `/resume <id>`, and arrival order cannot tell them apart: with a `SessionStart` hook slower than about 10 s, Droid stops waiting for it on a switch and the old `other` reaches the listener first (124 of 124 switches at 11 s or more on `/tree` and `/resume <id>`; at 9 s or less it never did, in 224). Instead, a `SessionEnd` of any `reason` that carries the row's owner process and names the pane's current lead starts one watch per row on the host that owns the process. The watch probes the captured pid and start time at 0.25 s, then at doubling gaps up to 8 s, for about 90 s, because Droid's default hook timeout is 60 s and `droid` is still alive when the post lands at Ctrl-C and SIGTERM exits. It marks the row ended only when the probe returns `exited`. It stops early on any later hook from the same process, a lead change, or a cleared row. At the bound it leaves the row as it was, and the on-demand check (Resume, another process's hook) stays authoritative. These numbers are defaults to tune against measured exit latency. No condition reads a `clear`, a reason, or the order of events, so `/new`, `/clear`, `/tree`, `/resume <id>`, and the replacements nobody measured (`/sessions`, `/compress`, `/handoff`, a slow start on `/new`) share one rule. Every other `SessionEnd` is dropped and left to the process check: a child's, and one for a session that is not the lead. The reason is not read, because the probe decides. Two quick Ctrl+C send `prompt_input_exit` (Droid 0.245.1), and the reasons for `/exit`, SIGTERM, and SIGHUP were never measured. Claude's `agent_id` filter cannot serve, because Droid's child `SessionEnd` has none. A hook after the row is ended from that same process stays ignored, with no revival: a row marked ended drops every later hook from that process, `exited` lets Resume in new chat through, and ended now means the host proved the process gone, so a new `droid` (a new identity) becomes a fresh owner. The cost is that a real exit shows as ended seconds late, never early, and Resume asks or blocks until then. Without a captured identity (Windows, rows saved before the capture) a `SessionEnd` changes nothing and the verdict stays `unverifiable`. The watch runs where the process runs and reports the same `ended` presence Claude's exit does, so it needs no wire capability: local and managed hosts use the in-process check and a WSL distro its guest's presence path. A host with no host-side check, such as a relay that predates this rule, forwards `other` as an ordinary status update, and its SSH rows stay `unverifiable`.
- The host needs a query that joins a session id to the pane rows holding it and to each pane's verdict. Nothing does that today. It runs where the transcript lives.
- The Droid adapter reports its Droid session id as a provider handle (agent `droid`) and joins the shared ownership list. The vault lookup, `findOwnership`, `findResumeOwnership`, and the resume parser become a per-provider grammar table. The shared types are read widely, so run blast-radius first.
- Droid's grammar: `-r <id>`, `--resume <id>`, `droid resume <id>`, and `droid exec -s <id>` or `--session-id <id>` are refused while a chat owns the id. `--resume` with no id, `--last`, `droid resume` with no id, and a session link as the target count as target-less and are refused while any Droid chat is live. `--fork` is always allowed. The flags were read on 0.244.0 and are re-checked on the floor.
- Resume in new chat for Droid has its own eligibility branch: local only (ADR 0003), a non-empty session, the workspace path equal to the recorded folder, and no live holder. A held session gets its own blocked reason. A mismatch or a deleted recorded folder uses the existing `workspace` reason.
- The adapter loads a session with `droid.load_session` only, compares the folder Droid reports with the workspace, and closes the process on a mismatch. It never calls `droid.initialize_session` with an existing id, which writes a second file, and never calls `droid.change_working_directory`.
- The vault stops counting records with `visibility` `llm_only` or `user_only`, and `completion` lines, as messages, so a session that only failed to sign in is empty and cannot be resumed. A chat-owned Droid row shows the chat's title and link.
- Fork in terminal for Droid is `['droid', '--fork', id]`, and "Resume in New CLI" is offered on chat-owned Droid rows only, as for Claude and Codex. A row a terminal holds gets no fork button: it keeps Open terminal, and branching it is `droid --fork <id>` typed in a terminal. The command needs no prompt and restores the session's recorded folder, whichever folder the pane is in (0.238.0 and 0.249.0).
- Revisit this decision if Droid adds a session lock or tells a holder about another writer. Revisit Fork into new chat if Droid lets `--fork` take a folder over `stream-jsonrpc` with no prompt.
